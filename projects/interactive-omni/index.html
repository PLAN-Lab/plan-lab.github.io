Native Real‑Time Interactive Omni Intelligence

A Unified Framework

The survey connects omni intelligence (understanding, reasoning and memory) with omni interactivity (when to speak, wait, act or revise). Its real-time interaction requirements are continuous input, incremental state updates and output that can change during an ongoing interaction.

Read the paper PDF Browse all papers Cite

Multimodal input arrives continuously. A fast foreground process manages interaction timing, including backchannels, turn gaps and yielding under barge-in. Slower reasoning and tool calls run asynchronously in the background, and their results must be validated against the current interaction state before use. Interactive Omni Intelligence

Smart is not enough. A live assistant also has to be on time.

Omni models can now see, hear and talk. Most still wait for a finished prompt before they answer. Real conversations do not wait. Audio and video keep coming while the model thinks, and people pause, overlap, interrupt and change their minds. The survey asks how to keep a model's reasoning and knowledge while it works inside that kind of live exchange.

Pillar one

Omni Intelligence

What the system understands across modalities.

  • Perceive
  • Remember
  • Reason
  • Predict
  • Read social cues
  • Ground facts

Perceive, update the state, choose to act, wait or revise, observe, repeat.

Pillar two

Omni Interactivity

When and how the system acts while the exchange unfolds.

  • Respond fast
  • Take turns
  • Handle interruption
  • Speak up unprompted
  • Adapt
  • Stay in control

Streaming input

Input arrives incrementally as audio and video streams, text updates, screen-state changes and tool feedback, rather than as a single completed prompt.

Evolving state

The system incorporates new information into its interaction state while it is still processing earlier input or producing a response.

Online response control

The system can initiate, revise or stop outputs, including speech, text, tool calls and interface actions, during the interaction, without waiting for a fixed end-of-turn boundary.

The Intelligence–Interactivity Trade-off

Adapted systems keep strong pretrained reasoning, but timing is spread across several parts. Model-native systems learn timing directly, but need synchronized data and training that keeps earlier skills. Multi-rate designs run fast and slow processes side by side, and every late result has to be checked against the current state before it is used.
